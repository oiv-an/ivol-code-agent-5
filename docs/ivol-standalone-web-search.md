# Отдельный поиск по интернету

Кнопка с глобусом в нижней строке чата открывает отдельное окно поиска. Пользователь вводит запрос, нажимает «Найти» и получает ответ с доступными ссылками на источники. Окно не является новой задачей или сообщением в существующей задаче.

## Подключение

- Используется сохранённый активный профиль OpenAI Compatible: его адрес, ключ, настройки TLS и отдельная модель нативного поиска.
- Это тот же механизм нативного поиска через Responses API, который используется инструментом `web_search`. Обычные запросы задачи продолжают использовать свой прежний протокол.
- Явное нажатие кнопки поиска не требует включения автоматического веб-поиска у основной модели и не меняет эту настройку.
- Поиск доступен параллельно работе основной задачи. Он не получает историю задачи, инструкции проекта, открытые файлы или содержимое редактора.
- Для других типов провайдеров кнопка пока недоступна. Провайдер выбранной модели должен поддерживать нативный поиск; наличие кнопки не гарантирует поддержку со стороны сервера.
- Поиск может расходовать оплачиваемый лимит провайдера. В окно выведено предупреждение; расход не записывается в статистику основной задачи.

## Результат и сохранение

- В окне остаётся только один последний поиск. Закрытие окна, смена профиля/настроек подключения или удаление панели очищают его локальное состояние и запрашивают отмену незавершённого поиска.
- Отмена поиска не отменяет задачу. Остановка работы на стороне сервера зависит от поддержки отмены провайдером.
- Запрос ограничен 8 000 символами, локальное ожидание — тремя минутами, ответ — 48 000 символами и 32 источниками. При обрезке ответа отображается предупреждение.
- Результаты не сохраняются автоматически в проект, историю чата или настройки. Запрос отправляется настроенному провайдеру; его правила хранения данных остаются за пределами контроля плагина.
- «Сохранить» открывает системный выбор файла, по умолчанию в папке Downloads. Только после выбора пользователем создаётся Markdown-файл с запросом, ответом и источниками. Существующий файл не перезаписывается: нужно выбрать новое имя.
- Закрытие или замена поиска до подтверждения диалога сохранения отменяет отложенную запись.
- В окне разрешены только явные ссылки HTTP(S) без имени пользователя и пароля. HTML и изображения из ответа не исполняются и не загружаются. Сохранённый Markdown содержит ответ провайдера и остаётся недоверенным текстом.

## Общая реализация

Интерфейс и обработчик общие для VS Code и JetBrains. Для JetBrains также исправлена обработка Windows/UNC-пути в диалоге сохранения и убрано журналирование тела входящих сообщений webview. Сборка, установка и проверка в конкретной IDE — отдельные шаги; изменение исходников само по себе не обновляет установленные плагины.

## Проверка реализации

- 195 целевых backend-тестов проходят; 17 прежних тестов `ClineProvider` остаются пропущенными.
- 46 UI-тестов проходят: отдельный поиск, размещение в нижней строке, существующий выбор модели и приватность браузерного предпросмотра.
- Компиляция Kotlin и четыре теста Windows/UNC/default URI, две проверки приватности JetBrains bridge проходят.
- Общие проверки TypeScript и ESLint проходят: 33 задачи.
- Синтетический Storybook-пример проверен в браузере, в том числе при ширине 400 px. Он не обращается к провайдеру и не сохраняет файлы.
- Новые строки интерфейса добавлены на русском и английском. Общий поиск отсутствующих переводов продолжает сообщать о других языках и прежних пропусках; это не чистая проверка всех локалей.
- Реальный поиск через пользовательский провайдер, установка и запуск в каждой IDE в этой итерации не выполнялись. Ограничение длины результата не является жёстким ограничением размера сетевого JSON до его разбора.
